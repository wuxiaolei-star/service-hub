## 三、本轮发现并已修复的问题

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 质量门"失败"但 pytest 没跑 | 镜像 `ENTRYPOINT=service-hub-entrypoint` 先自举，缺 `HUB_HOST_DATA_DIR` 直接崩 | `docker run --entrypoint bash` |
| 2 | 用例 `test_nested_dockerfiles_...` FileNotFoundError | 运行时镜像不含 `git`，用例依赖 `git check-attr` | 加缺失即跳过（Actions 上有 git，保护仍在） |
| 3 | "备份失败并回滚"（实际容器没停） | `compose.yaml` 用 `${HUB_HOST_DATA_DIR:?}`，流水线没 export | pipeline 补 `export HUB_HOST_DATA_DIR` |
| 4 | 改了流水线却仍在跑旧逻辑 | bash 按字节偏移读运行中的脚本，checkout 后新旧混杂 | `pull-deploy.sh` 先 checkout 再 exec |
| 5 | **自动部署全程失败**（`status=1/FAILURE`） | `set -u` 下 `PIPELINE_ARGS` 未定义即退出；手动跑都带了该变量所以没暴露 | 改 `${PIPELINE_ARGS:-}` |
| 6 | 改一篇文档就触发 10 分钟全量部署 + 1~2 分钟中断 | 未区分改动范围 | 新增轻量路径：改动仅落在 `docs/*`、`*.md`、`README*`、`LICENSE`、`.git*` 时只记录发布不重建（主镜像 Dockerfile **不 COPY 这些路径**，故镜像内容等价） |

| 7 | 轻量路径对中文文档不生效（仍走 10 分钟全量） | git 默认把非 ASCII 路径输出为八进制转义（`"docs/guides/\347\263\273...md"`），匹配不上 `docs/*` | `git diff` 加 `-c core.quotePath=false` |
| 8 | 定时器与手动部署重叠时 systemd 记 `Failed unit` | 并发锁按失败码退出（1），实际是"已有部署在跑"的正常情况 | pipeline 锁冲突退 3；pull-deploy 收到 3 视为空操作；单元加 `SuccessExitStatus=0 2 3` |

> 第 5 条是最严重的一条：修复前 timer 每次触发都以失败告终，CD 实际处于"装好但不工作"的状态。
> 第 6 条同时刷新了 `$REMOTE_DIR/deploy/ci/` 稳定副本——timer 执行的是它，否则脚本修复要等下次 `install-poller.sh` 才生效。
> 第 7、8 条是在修复后首次自动部署时暴露的：前者让轻量路径形同虚设，后者制造假故障告警。

**自动链路端到端验证（11:12~11:26）**：timer 自动触发 → 全量部署 `6a15b32`（质量门 953 passed / 706 s，
805 s 完成，三容器 healthy）；3 分钟后 timer 再次触发，`c72323f` 为纯文档改动 →
`docs-only change (1 files)` → `LIGHTWEIGHT DEPLOY FINISHED`，`elapsed=0s`，`result=SUCCESS-LIGHTWEIGHT`，
期间服务未重启、无中断。即：**改文档不再触发重建，改代码才重建，且全程无人干预。**

## 七、2026-09-25 下午执行记录（O-1/O-2/O-3/O-4/O-5/O-6/O-10/O-12）

核查结论先行：自动链路（push → Actions → timer 拉取部署 → 轻量路径）实测全部正常，
部署机三容器 healthy、磁盘 23 G/40 G、`.deployed-commit = origin/main = 1119248`。
另发现一个**新问题**并随本轮修复：原回滚逻辑是"恢复 data 后用 `/opt/service-hub/build.sh`
重建镜像"，而 stage 1 已经 checkout 到**新** commit——即旧回滚只回滚数据、代码仍是失败的
新代码。O-1 的 tag 化从根上解决了这一点。

| # | 改动 | 落点 |
|---|---|---|
| O-1 | 镜像按 commit 打 tag：`deploy/ci/build-images.sh`（入库，替代服务器本地 build.sh）产出 `:1.0.0-<sha>` 并移动 `:1.0.0-linux-amd64`；上一版保留为 `:rollback-target`；回滚 = 恢复冷备 + 重打移动 tag（秒级、且代码真正回到上一版）；成功后清理更早 commit tag + prune 悬空层 | `deploy/ci/build-images.sh`（新）、`deploy/ci/deploy-pipeline.sh` |
| O-2 | 服务器侧质量门默认关闭（`HUB_PIPELINE_GATE=0`，Actions 已全量跑）；`HUB_PIPELINE_GATE=1` 或 `--run-gate` 可手动补跑 | `deploy/ci/deploy-pipeline.sh` |
| O-3 | 插件包内容哈希缓存：键 = sha256(manifest + 源码摘要 + Dockerfile + 三个 hub 包源码树 + 基础镜像 ID + 镜像源参数 + zstd 等级 + arch)，命中且 sha256 校验通过即跳过 docker build/save/zstd/tar 全程；缓存目录默认 `<output>/.pypkg-cache`，`HUB_PLUGIN_CACHE_DIR` 可迁移、`HUB_PLUGIN_CACHE=0` 可关闭；仅保留最新 3 份。conda-pack 不缓存（依赖宿主机状态，无法用本地键钉住） | `packages/hub-publisher/src/hub_publisher/builder.py` + 8 个新测试 |
