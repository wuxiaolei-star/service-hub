# 第一部分 系统概览

```
浏览器 ──TLS:8443──▶ nginx edge ──▶ web 控制台(SPA)
                                  └▶ hub-api(FastAPI, SQLite)
                                        ├─ conda-runner（conda-pack 插件，宿主进程）
                                        ├─ docker-runner（docker 插件，无网络/只读/降权容器）
                                        ├─ cleaner + scheduler（保留期清扫/调度）
                                        └─ service-manager
GitHub ──四门 CI──▶ 服务器 strict 门禁 ──▶ 自动部署（绿才部署，失败自动回滚）
```

- 三容器：`hub-api`、`hub-web`、`hub-edge`（nginx TLS），compose 编排，唯一对外端口 8443。
- 插件双运行时：docker（默认，强沙箱）与 conda-pack（宿主进程，179MB 级轻量包）。
- 交付链：`git push` → GitHub Actions 四门（secrets/backend/web/image）→ 服务器每 3 分钟
  strict 门禁（check-runs 绿才部署）→ 自动部署 + 业务走查。失败自动回滚（切 tag）。

**v1.2 相对 v1.1 的重大变更**（详见各章）：
1. 作业保留期 **30 天 → 7 天**（磁盘事故治理，§2.7）；
2. 企微/钉钉通知环节**取消**，部署结果以 `releases.log` + journalctl 为准（§4.2）；
3. CI 门禁默认 **strict**（API 不可达也扣住，§4.1）；
4. 新增受守卫的**构建删除**端点（`dry_run` 演练模式，§4.4）；
5. 作业语义收紧：required 输出缺失=FAILED、每用户 PENDING 上限 10、流水线首步也受配额（§2.4）。

# 第二部分 用户视角

## 2.1 控制台访问

- 地址：`https://${HUB_HOST}:8443`（自签证书，浏览器需信任一次；证书有效至 2028-12）。
- 账号：admin 或经分配的账号；首次登录若带 `must_change_password` 标记请立即改密
  （改密成功会自动清除服务器上的 bootstrap 凭据文件）。会话 Cookie 自 v1.2 起带
  Secure 标志，仅经 HTTPS 传递。
- 角色：viewer（只读）→ operator（发起作业）→ publisher（装/停/废插件）→ admin（全权 + 删除 + 指标）。

## 2.2 插件浏览与构建状态机（所有角色可见）

构建状态机（v1.2 控制台已完整渲染五态，含**已废弃**徽章）：

```
INSTALLING → READY → ENABLED → DEPRECATED（单向，控制台显示"已废弃"灰徽章）
                    ↘ FAILED
```

- 只有 ENABLED 构建能接新作业；DEPRECATED 与 READY（已停用）均不接。
- **DEPRECATED 不可重新启用**（单向语义）。如需恢复同版本服务：以新版本号重装并启用新构建。
- admin 可对 DEPRECATED 构建执行**删除**（不可逆，见 §4.4）；删除前控制台不提供该操作，
  需经 API（先 deprecate → dry_run 演练 → DELETE）。

## 2.3 发起作业（operator 及以上）

- 输入文件：按 manifest 声明的扩展名/数量/大小校验；分片上传合并后总量超限返回
  **413 `UPLOAD_TOO_LARGE`**（v1.2 新增合并后二次校验）。
- 参数：类型/枚举/上下限校验；**datetime 参数必须为 ISO8601**（`2026-09-30T12:00:00Z`
  或带时区偏移，v1.2 新增强校验），否则 422 `JOB_REQUEST_INVALID`。
- 作业语义（v1.2 收紧，务必知悉）：
  - **required 输出缺失 = FAILED**：manifest 声明 `required: true` 的 file/files 型输出若插件
    未产出，作业翻为 FAILED，错误码 `PLUGIN_OUTPUT_MISSING`（object 型输出暂不强制）；
  - **per-build 并发闸**：同一构建的活跃作业（PENDING/PREPARING/RUNNING）达到
    `execution.concurrency` 时返回 **409 `PLUGIN_CONCURRENCY_LIMIT`**（控制台已有人性化
    文案；定时调度同样受限，被拒后下一轮自动恢复）；
  - **每用户 PENDING 上限**：单人最多 10 个 PENDING 作业，超限 **409
    `USER_PENDING_QUOTA_EXCEEDED`**（终态释放后自动恢复）；
  - **流水线首步作业同样受配额**（v1.2 闭合同类旁路）；
  - rerun 与 create 适用完全相同的配额与闸（v1.2 前 rerun 绕过，已修复）。
- 资源限制（B7）：manifest 可声明 `execution.memory_mb` / `execution.cpus`，只能**收窄**
  平台默认（2048MB / 1.5 核，实测真实样本峰值 71.9MiB）；OOM（退出码 137）→ FAILED。

## 2.4 作业跟踪

- 状态机：PENDING → PREPARING → RUNNING → SUCCESS / FAILED / CANCELLED / TIMED_OUT。
- 日志：详情页实时流（SSE，v1.2 起异步化，不再挤占服务线程）+ 游标分页 + CSV 导出。
- 输出下载：详情页逐文件下载（下载动作写入审计）。
- rerun：从终态作业一键重跑；v1.2 起 rerun 与 create 适用相同配额/并发闸（可能 409）。
- **失败排查（failure_class 五分类）**：

| 类 | 典型码 | 第一动作 |
|---|---|---|
| plugin | `PLUGIN_*` | 读 error_summary 与作业日志尾部；插件代码问题 |
| timeout | `JOB_TIMED_OUT` | 评估超时上限或优化插件；或声明更大 resources |
| cancelled | — | 确认是否人工/调度取消 |
| runner | `RUNNER_FAILED` / `HUB_RESTARTED` | 基础设施问题，看 runner 日志与主机 |
| system | 其他 | 带 job_key 找运维 |

## 2.5 调度与统计

- 调度（schedules）：interval 或 cron；被并发闸 409 拒绝的轮次自动顺延，下轮恢复。
- 统计：`/api/v1/jobs/stats` 默认按天；**`?by=plugin`** 返回每插件
  {total/success/failed/cancelled/timed_out/failure_classes/p50/p95}（v1.2 新增）。

## 2.6 数据生命周期（v1.2 重大变更）

- **作业与输出保留 7 天**（原 30 天，2026-09-29 磁盘事故治理）：终态作业 7 天后被
  cleaner 清除（工作区/输出/回调一并删除），rerun 与下载随之失效。需要长期留存的
  输出请在 7 天内下载归档。
- 上传文件 TTL 与输入快照随作业清理。

## 2.7 作业失败之外的安全语义速查

| 现象 | 含义 |
|---|---|
| 409 `PLUGIN_BUILD_SCHEDULE_REFERENCED` | 删除的构建是某启用调度的最后可服务构建 |
| 409 `PLUGIN_BUILD_PIPELINE_REFERENCED` | 流水线步骤仍引用该构建 |
| 409 `PLUGIN_BUILD_IN_USE` | 活跃作业占用中 |
| 422 `PLUGIN_PACKAGE_SIGNATURE_INVALID` / `_REQUIRED` | 包签名无效 / 强签模式缺签名 |
| 403（runner 接口） | 非法 token，含非 ASCII 头（v1.2 由 500 修正为 403） |

# 第三部分 插件作者视角（速查，详见《插件开发者指南》）

| 命令 | 用途 |
|---|---|
| `hub-plugin validate <dir> [--runtime] [--package x.pypkg]` | 本地校验项目/包（布局、checksums、build.json 一致性） |
| `hub-plugin dev <dir> --mode python\|docker [--input ...] [--param k=v] [--keep]` | 本地试跑，产出过协议校验 |
| `hub-plugin build <dir> --runtime --arch --output` | 打包 .pypkg |
| `hub-plugin keygen --out-prefix <p>` / `hub-plugin sign <pkg> --key <k>` | Ed25519 密钥与签名（可选依赖组 `[signing]`） |

- 插件约束速记：docker 运行时 = 无网络、只读 rootfs、65532 用户、cap_drop ALL、
  按 digest 钉死；conda 运行时 = 宿主进程（RLIMIT 资源上限、无容器隔离）。
- 事件/日志纪律（v1.2）：单条事件 ≤4096 字符、每作业事件条数/字节有上限（超限截断并
  记系统事件）；**不要写 `logs/events.jsonl`**（服务端事件已移至 `meta/`，插件不可见）。
- required 输出务必产出（file/files 型缺失即 FAILED）；datetime 参数用 ISO8601。
- 一致性验收：把用例接入 `tests/plugins/harness.py`（约 18 行/用例）。

# 第四部分 运维 / 开发视角

## 4.1 交付链与门禁

- `git push` → Actions 四门（secrets/backend/web/image）→ 服务器 strict 门禁：
  **check-runs 非绿一律扣住**（pending/红/API 不可达/响应不可读均扣住；唯一放行方式是
  显式 `HUB_CI_GATE=wait`，且每次 fail-open 放行会向 `releases.log` 记 `result=WARNING`）。
  被 CI 取消的 run 同样按红处理。
- 环境开关：`HUB_CI_GATE=strict|wait|off`、`DEPLOY_REPO_SLUG`、`HUB_PIPELINE_GATE`
  （服务器侧容器内 pytest 补门，默认关）、`HUB_MIN_FREE_MB=2048`（磁盘水位）。

## 4.2 部署结果观测（v1.2：企微/钉钉通知已取消）

- **唯一结果通道**：`tail -f /opt/service-hub/deploy/ci/releases.log` +
  `journalctl -u service-hub-deploy -f`。轻量文档批记 `SUCCESS-LIGHTWEIGHT`；
  CI 失败扣住记为门禁行（不写 releases.log）；fail-open 放行记 `result=WARNING`。
- 按用户决定（2026-09-26），企微/钉钉 bot 通知环节已**整体移除**（notify() 与
  `HUB_DEPLOY_WEBHOOK_URL` 已不在代码与文档中）。若日后需要告警，另行立项。

## 4.3 回滚与恢复

- **代码回滚（秒级）**：`git revert <sha> && git push`（自动重部署）；或切 tag：
  `docker tag python-service-hub:rollback-target python-service-hub:1.0.0-linux-amd64`
  + web 同理 + `docker compose up -d`。
- **数据回滚边界**：流水线冷备（0600）含 environments 与 secrets；服务内 API 备份
  **不含** environments/secrets（恢复后 conda 构建需按 build_key 重装，runner token
  会自动再生）。两条通道语义详见运维手册备份节。
- 红线：**任何形式的 `docker image prune`**；**不得手改 `/opt/service-hub/src`**。

## 4.4 插件构建删除（B4b，admin）

```bash
# 1) 废弃（冷却）
curl -X POST -H "$AUTH" .../api/v1/plugin-builds/<KEY>/deprecate
# 2) 演练：返回守卫评估 + 动作清单，零变更
curl -X DELETE -H "$AUTH" ".../plugin-builds/<KEY>?dry_run=true"
# 3) 执行（先 DB/storage 消除引用，后按 sha256 精确删镜像；绝不 prune）
curl -X DELETE -H "$AUTH" ".../plugin-builds/<KEY>"
```

- 守卫 409 码：`PLUGIN_BUILD_NOT_DEPRECATED` / `PLUGIN_BUILD_SCHEDULE_REFERENCED`
  / `PLUGIN_BUILD_PIPELINE_REFERENCED` / `PLUGIN_BUILD_IN_USE`。
- 恢复路径：删除会释放同版本唯一约束槽（同版本可重装）；物料不可恢复，删前 registry 留档。

## 4.5 巡检清单（每日）

1. 三端健康：18000 health / 18080 web-health / 8443 edge-health；
2. `releases.log` 尾部有无 WARNING/失败；`journalctl -u service-hub-deploy` 有无
   连续扣住（CI 黄/红）；
3. 磁盘 `df -h /`（水位告警 2048MB 拒部署；正常稳态 6–9GB 可用）；
4. 调度成功率（`/jobs/stats`）；
5. 审计 `environments_orphans_detected` 事件（B4a 扫描，只报告）。

## 4.6 磁盘事故处置卡（2026-09-29 实录）

症状：api 崩溃循环 `sqlite3.OperationalError: disk I/O error`。
处置：`ls -1t /opt/service-hub/data-{hot,cold}-*.tar.gz | tail -n +2 | xargs -r rm -f`
→ `docker compose up -d` → 三端验证。预防：保留期 7 天（本版已生效）+ 水位拒部署。
