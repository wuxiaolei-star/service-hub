## 批次二：后端短期梯队（已完成实施并合并 main）

7. **#9 写锁窗口收窄（最先做，风险最高）**：JobService.create 两阶段化 ✅
   - 落地：`job_key` 与 `created_at` 提前到 add 之前生成（`_public_id("job")` / `_utc_now()`）；`JobWorkspaceService.prepare` 拆为 `stage()`（无 DB：建目录+输入复制+完整性校验+构建 JobRuntimeSpec+写 job.json）与 `install()`（原子改名+回写 `workspace_path`/`job_json`）
   - 事务外 stage → 事务内 add/flush → install → commit；SQLite 写锁窗口从「整个输入复制」收窄到「flush+改名+commit」尾部
   - 失败路径：`_rollback_create` 统一回滚事务 → `discard(staged)`（幂等，`ignore_errors=True`）→ 已 install 则 `storage.remove_job_workspace(job_key)` 清孤儿目录（清理失败只记 exception 日志，不掩盖原错误）
   - 进程中断兜底：`sweep_stale_temporaries()` 在 lifespan 启动清扫 `jobs/.tmp-*` 超 24h 目录（main.py）
   - 附带修正：stage 期构建 runtime spec 走 `job.plugin_build.plugin_version` 懒加载会触发 autoflush 把未入 session 的 Job 卷入 cascade（SAWarning），加 `_no_autoflush` 上下文消除非确定性
   - 测试：stage 失败 / install 失败 / commit 失败 / 孤儿清扫四类场景（tests/server/test_job_workspaces.py）
8. **#7 async 上传同步写盘** ✅：upload_file 的 multipart parser 回调与 upload_chunk 的 `sink.write` 循环均移入 `run_in_threadpool`，事件循环不再被大文件写盘与 SHA256 阻塞
9. **#10 配置收拢** ✅：HubSettings 新增 `service_manager.base_url`（默认 `http://127.0.0.1:8001`，行为不变）与 `docker.host_data_root`；`from_yaml` 沿用 env 合并（`HUB_SERVICE_MANAGER_URL` / `HUB_DOCKER_HOST_DATA_ROOT` 由 entrypoint 从 `HUB_HOST_DATA_DIR` 导出后合入），**部署启动链行为等价、未破坏**；`HUB_CONFIG_PATH` 缺失改抛明确 HubError
   - compose 核查结论：hub-api 与 service-mgr 均 network_mode: host，默认 base_url 不变；deploy/ 脚本不受影响
10. **#8 SSE 降级为最小改动** ✅：日志流路由不再持有请求级 session，改由 `app.state.session_factory` 每轮循环短借短还（最长 300s 的连接不再长期占用一个 DB 会话）；**未动同步生成器模型**

质量门：全量 `pytest -m "not integration"` 930 passed；`ruff check .` 与 `mypy packages` 全绿。
**本机环境性失败 5 项（与改动无关，已在干净 main 上 stash 对照复现）**：`tests/sdk/test_context.py::test_output_file_rejects_existing_symlink_that_escapes_root`（沙箱符号链接语义）、`tests/deploy/test_release_scripts.py` 4 项（`bash script.sh` 被 wsl.exe 黑名单拦截）。
