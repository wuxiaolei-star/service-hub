## 批次一：后端快速优化（已完成实施，收尾中）

已实施并通过事实核查：
1. **B1** list_jobs 加 joinedload/contains_eager 消 N+1（services/jobs.py，plugin_id 过滤时 contains_eager 复用过滤 join）
2. **B2** resolve_actor 结果缓存到 request.state，每请求凭证只解析一次（dependencies_auth.py）
   - 已知权衡：同一请求内第二次解析走缓存，毫秒级窗口内的会话吊销不再被同请求感知（TOCTOU 收窄），下一请求生效——可接受，已在此记录
3. **B3** JobService.logs 改流式按行读取，内存 O(1)（IO 仍为全文件顺序扫描，符合预期）
4. **B4** 移除 models.py 死 TTL 默认值（修正：登录路径本就传配置；评审发现 3 处测试依赖旧默认值，已同步修复 test_auth_models.py×2、test_retention.py×1）
5. **B5** Alembic 0012 热路径索引：jobs(runtime_type,status,created_at) 复合 + schedules.next_run_at + job_callbacks.next_attempt_at 单列；与 models 元数据精确对齐，无命名冲突；已有数据表上加索引持写锁量级小，可接受
6. **B6** deliver_due 每回调投递后立即 commit（services/webhooks.py）

收尾动作：全量 pytest + ruff + mypy → 提交 → 合并 main → **worktree fast-forward 对齐 main**（redeploy.py 打包 worktree HEAD，不对齐则批次四部署错版本）

## 批次二：后端短期梯队（2~3 人日，按风险重排序）

7. **#9 写锁窗口收窄（最先做，风险最高）**：JobService.create 两阶段化
   - 前提契约（评审确认）：prepare 非纯文件复制——建目录/复制校验/构建 runtime spec（含 DB 懒加载）/写 job.json/原子改名；要求 job.id 非 None 且 job_key 由 flush 生成
   - 实施路径：把 job_key 生成提前到 add 之前；prepare 拆 `stage()`（无 DB）+ `install()`（改名+回写 workspace_path/job_json）两段；事务外 stage → 事务内 install+commit
   - 必配：stage 失败 / commit 失败 / 进程中断三场景测试；孤儿临时目录清理策略（启动清扫或 TTL）
8. **#7 async 上传同步写盘**：upload_file / upload_chunk 写盘+SHA256 移入 run_in_threadpool（routers/files.py）
9. **#10 配置收拢**：HubSettings 增加 service_manager.base_url / docker.host_data_root；HUB_CONFIG_PATH 缺失明确报错
   - 必配：核查 compose 文件与 deploy/ 脚本对 HUB_DOCKER_HOST_DATA_ROOT 环境变量的引用——settings 收拢后 env 行为变化可能破坏现有启动链，属隐性破坏性变更
10. **#8 SSE 降级为最小改动**：仅把 DB 会话改为每轮循环短借短还，**不动生成器模型**（1 人系统打不满 40 槽 threadpool，async 生成器重构收益/风险比不成立；完整改造移入中期演进）
