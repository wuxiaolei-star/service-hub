### 🟡 P1 — 影响「完全部署」的完整性

#### T5. 服务器端质量门（清单 7.1）—— 已启动，**卡在缺测试依赖**

- **现状**：已在服务器建好 `.gate-venv`（`--system-site-packages`，装好
  workspace 五个包 + `pytest pytest-timeout ruff mypy`），但首次运行**在收集阶段就中断**：

```
ERROR collecting tests/plugins/test_nc_to_shp.py
  tests/plugins/test_nc_to_shp.py:10: in <module>
      import h5py
  E   ModuleNotFoundError: No module named 'h5py'
7 deselected, 1 warning, 1 error in 4.69s
```

- **性质**：**测试依赖缺失，不是产品缺陷**。`test_nc_to_shp.py` 直接 `import h5py`，
  而 gate venv 没装 `h5py`；该模块也没有对应的 `pytest.importorskip` 兜底。
- **待做**（二选一）：
  - **A（推荐）**：给 gate venv 补装测试依赖（`h5py`，以及清单里跑全量所需的其它测试依赖），
    然后重跑；
  - **B**：给 `tests/plugins/test_nc_to_shp.py` 加 `pytest.importorskip("h5py")`，
    让缺依赖时**干净跳过**而不是中断整个收集 —— 这同时也修掉一个真实的健壮性缺陷
    （缺依赖不该让**整个套件**无法收集）。
- **完成判据**：`pytest -m "not integration"` 在服务器上跑完整，
  **确认本机那 5 个环境性失败在此通过**，并记录实测数字。
- **注意**：该模块 `import h5py` 的位置（模块顶层）值得留意 ——
  它使「缺依赖」升级为「全量收集失败」，影响面被放大。

## 五、附：本轮已关闭的缺陷（D-25 ~ D-30）

| 编号 | 一句话 |
|---|---|
| D-25 | 控制台请求 `/pipeline-runs`，后端只服务 `/pipelines/runs` → 运行记录必然 404 |
| D-26 | 自动化套件不幂等（重跑撞 409），且断言与其占位输入**相反** |
| D-27 | 生命周期套件未随 V3.0 拓扑与 V2 鉴权同步（服务集断言、上传缺 token、凭据取错来源） |
| D-28 | 宿主机套件的 Compose 调用方式与任何真实部署都不一致，必然取不到运行中的栈 |
| D-29 | 进程状态断言只认 3 个进程，V3.0 实为 6 个 → 健康容器被判失败 |
| D-30 | 自动化套件的回环前提未声明，放错运行位置会表现为「webhook 坏了」 |

**D-30 的取证要点**（可用于今后排查同类问题）：服务器 `job_callbacks` 表中
`SUCCEEDED` 的记录全部落在套件**容器内**运行的时段，改用**宿主机**运行器后全部变为
`Connection refused` —— 证明投递方向正确，是**运行位置**变了。
