## 阶段一：可用性速赢（预计 2~3 人日）

目标：解决最影响日常使用的 5 个问题，全部是局部改动。

### 1.1 侧边栏菜单分组 + 全局主按钮
- 文件：`web/src/layouts/AppLayout.tsx`
- 改动：
  - `menuItems` 改为 antd Menu 分组结构（`type: 'group'`）：总览 / 资产（插件、仓库、文件）/ 运行（任务、定时任务、管道、服务）/ 管理（系统、用户、API Key、审计）。
  - 移除「新建任务」一级菜单项；侧栏底部（折叠按钮上方）新增主按钮「＋ 新建任务」，`type="primary" style={{ width: '100%' }}`，跳 `/jobs/new`。
  - 选中态样式：`.app-sider .ant-menu-item-selected` 增加 `box-shadow: inset 3px 0 0 var(--colorPrimary)` 左侧指示条，与边框色 `#DCE8F5` 区分。
- 验收：分组标题在折叠态自动隐藏；截图与测试 `AppLayout.test.tsx` 更新。

### 1.2 任务表短 ID + 可点详情
- 文件：`web/src/pages/DashboardPage.tsx`、`JobsPage.tsx`、`JobDetailPage.tsx`
- 改动：ID 列渲染 `id.slice(4, 14)`（去掉 `job_` 前缀取 10 位），`Tooltip` 全文 + `Typography.Text copyable`；行点击进详情。
- 验收：列宽从 ~25% 降到 ~12%；详情页保留完整 ID 与复制按钮。

### 1.3 任务表新增耗时列 + 状态筛选
- 文件：`DashboardPage.tsx`、`JobsPage.tsx`；依赖后端现有字段（`started_at`/`finished_at`，如缺则用 `created_at` 近似并在列头注明）。
- 改动：表格上方 `Segmented`（全部/运行中/成功/失败）前端过滤；耗时列 `duration` 计算函数放 `utils/`。
- 验收：筛选纯前端实现，不改 API。

### 1.4 相对时间 + 数字对齐
- 文件：新增 `web/src/utils/time.ts`（`formatRelative` + `formatAbsolute`），所有列表页替换。
- 改动：列表显示「2 小时前」，`Tooltip` 显示绝对时间；数字/时间列统一 `font-variant-numeric: tabular-nums`（写入 `styles.css` 全局类）。

### 1.5 健康检查降频 + 退避
- 文件：`AppLayout.tsx`
- 改动：`refetchInterval` 从 10s 改为函数形式：UP 时 30s、错误时 60s（`queryFn` 失败次数乘 2，封顶 120s）。
- 验收：DevTools Network 面板确认请求频率；`服务正常/离线` 文案与状态点展示不变（去掉 Tag+Badge 双重表达，只留 `Badge status` + 文字）。

## 阶段二：视觉体系与层级（预计 3~4 人日）

目标：解决「不大气」——建立设计 token、重构页头、提升信息层次。

### 2.1 Design Token 展开
- 文件：`web/src/theme/theme.ts`
- 改动：补全 token——间距阶（`margin/cardPadding`）、字号阶（h1 20 / h2 16 / body 14 / caption 12）、`colorSuccess/Warning/Error/Info`、`fontSize`、`controlHeight`；`components` 中细化 `Table`（`headerBg`、`rowHoverBg`）、`Card`（去阴影改 0.5px 边框，或保留轻阴影二选一定稿）。
- 顺手支持暗色模式：token 按 `prefers-color-scheme` 或手动开关切两份；暗色为可选项，不阻塞发布。

### 2.2 页头与面包屑
- 文件：`AppLayout.tsx`、`components/PageHeader.tsx`
- 改动：顶栏左侧渲染面包屑（由 `useLocation` + 路由表映射，如 `总览 / 任务 / job_37841e59`）；页面内标题统一走 `PageHeader`（标题 + 副标题 + 操作区右对齐），删除各页自带的标题写法。

### 2.3 KPI 卡改造
- 文件：`DashboardPage.tsx`
- 改动：
  - 每卡加图标（antd icon 置于浅色圆底）+ 可点击跳转（进行中任务→任务页筛选、插件→插件页）。
  - 「可用 Build」拆两行：主数字 + 副文案「1 已启用 / 0 就绪」。
  - 新增「今日成功率」卡（成功数/总数，纯前端由最近任务列表聚合；若接口无全天数据，标注「最近 100 条」口径）。
  - 卡片背景 `#F8FAFC` 无边框，与下方白卡拉开层次。

### 2.4 空态 / 骨架屏统一
- 文件：`components/EmptyState.tsx` 复用；各列表页加载态统一 `Table loading` + 首屏 `Skeleton`。

验收：整体截图对比评审（对照已出改版示意图 `dashboard_redesign_mockup`）；13 个页面全部过一遍视觉走查。

## 阶段三：体验深化（预计 3~4 人日，可按需裁剪）

### 3.1 失败原因进列表
- 任务表失败行下加一行摘要（取日志首条 error，截断 60 字），点击直达日志 tab。需要后端在列表接口加 `error_summary` 字段——**这是唯一可能动后端的点**，若不做则降级为详情页内优化。

### 3.2 角色化菜单
- 文件：`AppLayout.tsx`（配合已有 `fetchMe` 的 role）
- 改动：`menuItems` 按 role 过滤/禁用：viewer 隐藏「管理」组操作类入口；被 403 的菜单项禁用 + Tooltip「需要 XX 角色」。

### 3.3 响应式修正
- 文件：`styles.css`
- 改动：删除 `body { min-width: 1280px }`；表格容器 `overflow-x: auto`；KPI 卡栅格 `repeat(auto-fit, minmax(220px, 1fr))`；补充 768px 断点下内容区 padding 16px。

### 3.4 i18n 预留（可选）
- 引入 react-i18next，抽离文案层；13 个页面一次性抽完约 1 人日，可与阶段三并行。

## 阶段四：演进项排期（2026-09-23 纳入，未开工）

> 前三阶段收官后剩余的可选项，按优先级排序。可与《后端架构优化清单-2026-09.md》的
> 「立即做」梯队并行推进，两者互不阻塞。

### 4.1 暗色模式（优先级最高，约 2 人日）
- 依赖：阶段二已铺好 design token 地基（`theme.ts` 完整 token 层）
- 改动：token 拆 light/dark 两份 + `ConfigProvider` 切换；顶栏加切换开关，偏好存 localStorage + 跟随系统；图表配色变量与 4.2 的选型共用一套（选型在 4.2 定）
- 范围控制：token 与 components 两层都要拆亮/暗两份（components 段的 lightSiderBg/headerBg/itemSelectedBg 等亮色专用值不拆则暗色下会破）；登录页/概览页先行，其余页面按 token 覆盖度自然继承
- 验收：13 页截图走查（亮/暗两轮），focus-visible 与状态色对比度达标

### 4.2 任务耗时统计图表（约 2~3 人日）
- 改动：概览页新增耗时分布图（P50/P95，按插件分组）+ 近 7 天成功/失败趋势；数据源为现有 jobs 列表（最近 100 条口径），不新增后端接口
- 依赖决策：引入图表库（推荐 `@ant-design/charts`，与 antd 5 同源；或轻量自绘 SVG）
- 验收：空数据态、单任务态不破版；图表随筛选联动

### 4.3 i18n（约 1~2 人日，触发条件：有对外/多语言需求时开工）
- 改动：引入 react-i18next，抽离 13 页文案层；key 按 `<页面>.<组件>.<要素>` 命名
- 风险：文案抽取会大范围触碰 `.test.tsx` 断言 → 单独一个批次提交，vitest 作为提交门
- 明确暂缓理由：当前无多语言需求，纯成本项；页面数量增长后再做收益不变

### 阶段四顺序建议

```
4.1 暗色模式 ──→ 4.2 耗时图表 ──→ 4.3 i18n（条件触发）
```

4.1 收益/成本比最高且地基已就绪；4.2 需先定图表库选型；4.3 无触发条件不开工。

## 风险与对策

1. **测试回归量**：每页都有 `.test.tsx`，布局/列改动会批量破坏断言 → 每批改动同步更新测试，`vitest run` 作为提交门。
2. **D-33 教训（产物验证）**：TS 层全绿不代表真实页面正确 → 每阶段结束后用 Edge 走查脚本（`.deploy-tools/walkthrough-*.mjs`）对 13 页截图比对，并 grep 构建产物关键字。
3. **暗色模式范围蔓延**：先只做 token 层两份定义 + 登录页/概览页适配，其余页面按需跟进，不追求一次全覆盖。
4. **不做的事**：不换组件库、不引额外 UI 依赖、不改路由结构（避免破坏现有测试与审计口径）。
