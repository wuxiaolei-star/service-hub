## 一、系统是什么

Python Service Hub 是一个**离线、单机的 Python 算法插件调度服务**：

- 算法团队把 Python 脚本包装为**插件**（`.pypkg` 包），上传到 Hub 注册；
- 业务系统通过 REST API 或管理台上传数据文件、创建任务（Job）、下载结果；
- Hub 在隔离的 Docker 容器或 conda-pack 环境中执行算法，保存日志和输出。

**一个类比**：Hub 就像一个"算法应用商店 + 运行时"——算法开发者发布插件，
业务消费者使用插件处理数据。

## 三、当前架构（V4.0）

### 3.1 部署拓扑

```text
浏览器 / hubctl / 业务系统
         │ HTTPS (edge TLS 终止，自签或正式证书)
         ▼
  127.0.0.1:8443 ── edge 容器 (nginx:alpine)
         │                    ├── / → SPA 静态页面
         │                    ├── /api/v1 → 代理到后端
         │                    └── /internal/v1 → 404（拒绝）
  127.0.0.1:18080 ── service-hub-web 容器 (React SPA + Nginx)
  127.0.0.1:18000 ── service-hub 后端容器 (supervisord 管理多进程)
         ├── hub-api          FastAPI + SQLite
         ├── conda-runner     一次性 conda-pack Job
         ├── docker-runner    一次性 Docker Job
         ├── cleaner          文件/审计/会话保留清理
         ├── scheduler        回调投递/定时触发/管道步进
         └── service-manager  长期 Docker 服务管理
```

### 3.2 后端分层

```text
packages/hub-server/src/hub_server/
├── kernel/               ← 最小内核（不可替换）
│   ├── protocol.py         FeaturePlugin 协议 + PluginContext + 事件类型
│   ├── registry.py         插件发现/拓扑排序/依赖闭包校验
│   └── events.py           Event Bus（进程内同步 + SQLite outbox 跨进程）
├── plugins/              ← 功能插件（每个功能域一个自注册插件）
│   ├── auth_plugin.py      认证/用户/API Key
│   ├── files_plugin.py     文件上传/下载/查重
│   ├── jobs_plugin.py      Job 生命周期 + reaper + retention
│   ├── catalog_plugin.py   计算插件管理 + 仓库
│   ├── schedules_plugin.py 定时任务
│   ├── webhooks_plugin.py  回调投递
│   ├── metrics_plugin.py   Prometheus 指标
│   ├── quotas_plugin.py    配额执行
│   ├── backup_plugin.py    备份/恢复
│   └── audit_plugin.py     审计查询/导出
├── routers/              ← HTTP 端点（由插件声明挂载）
├── services/             ← 业务逻辑
├── models.py             ← ORM 模型（19 张表）
├── settings.py           ← 严格配置模型（extra=forbid）
└── main.py               ← app factory（Plugin Registry 挂载）
```

### 3.3 插件分类

| 类别 | 判断标准 | 可禁用 | 包含 |
|---|---|---|---|
| **基础插件** | 没有它系统无法完成"上传→建任务→取输出" | ❌ | auth, files, jobs, catalog |
| **公共插件** | 不提供用户功能，为其他插件提供基础设施 | ❌ | audit, metrics, retention, quotas |
| **扩展插件** | 增强能力，禁用后核心流程完全不受影响 | ✅ | webhooks, schedules, pipelines, registry, services, backup |

## 四、核心概念

### 4.1 两种"插件"

| | 功能插件（FeaturePlugin） | 计算插件（Compute Plugin） |
|---|---|---|
| 注册到 | Hub 内核（进程内 Python 模块） | Hub API（跨进程 Docker/conda 容器） |
| 生命周期 | Hub 启停 | 一次性 Job 或长期服务 |
| 隔离 | 同进程 | Docker 容器 / conda 环境 |
| 开发者 | 平台开发者（本仓库） | 算法团队（.pypkg 包） |
| 举例 | auth, files, jobs | nc_to_shp, raster_statistics |

### 4.2 Job 生命周期

```text
POST /jobs → PENDING → PREPARING → RUNNING → SUCCESS / FAILED / CANCELLED / TIMED_OUT
                                  ↓ CANCEL_REQUESTED
                               CANCELLED
```

### 4.3 角色权限

| 角色 | 能力 |
|---|---|
| viewer | 只读：查看列表/详情/日志 |
| operator | + 上传文件、创建/取消 Job、下载输出 |
| publisher | + 安装插件、启用/停用 Build |
| admin | + 用户管理、API Key、审计查询、服务管理 |

## 六、快速上手

### 6.1 环境准备

```bash
# Python 3.12 + 依赖
python -m venv .venv
.venv/Scripts/pip install -e "packages/hub-server[dev]" -e "packages/hub-contracts" ...

# 前端
cd web && npm ci
```

### 6.2 本地开发

```bash
# 后端测试
python -m pytest -m "not integration" -q

# 前端测试
cd web && npm run test:run

# lint + 类型检查
python -m ruff check .
python -m mypy packages
cd web && npm run typecheck && npm run lint

# 本地启动（需 HUB_CONFIG_PATH）
export HUB_CONFIG_PATH=config/hub.yaml.example
python -m uvicorn hub_server.main:app --port 8000

# 前端开发服务器（代理 /api → 8000）
cd web && npm run dev
```

### 6.3 生产部署

```bash
# 构建双镜像
docker build -t python-service-hub:1.0.0-linux-amd64 .
docker build -t python-service-hub-web:1.0.0-linux-amd64 web

# 启动
export HUB_HOST_DATA_DIR=/srv/service-hub-data
docker compose up -d

# 验证
curl http://127.0.0.1:8000/api/v1/system/health   # {"status":"UP"}
curl -I http://127.0.0.1:8080/                     # 200
```

详见 `docs/guides/单容器部署与脚本插件使用.md` 和
`docs/guides/Web管理台构建部署与使用.md`。

## 七、关键设计决策

| 决策 | 理由 |
|---|---|
| SQLite 而非 PostgreSQL | 离线单机交付，无外部依赖 |
| 不透明 token 而非 JWT | 可撤销、简单、安全 |
| 插件迁移与启用正交 | 禁用是逻辑卸载，数据保留 |
| 反应式依赖（Cordis 理念） | 依赖被禁用时依赖方收到通知并优雅降级 |
| 命名换装点（Cordis 理念） | storage/auth/database 在配置中切换实现 |
| 事件总线 outbox 模式 | 跨进程 at-least-once 投递，≤30s 延迟 |
| 同事务配额校验 | 上传/建 Job 与配额在同一 DB 事务，防超卖 |
