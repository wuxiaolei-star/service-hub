## 1. 版本定位

V3.1 在 V3.0（长期运行 Docker 服务）之上交付**稳定性与正确性**加固，消除三视角
推演确认的唯一"数周内必然劣化到不可用"问题（五处数据无界增长）、runner 崩溃后
的僵尸 Job 泄漏，以及两个正确性 bug（API Key 提权口子、版本排序）。零迁移、
零新表、零 API 破坏。

## 2. V3.1 新增能力

### 2.1 数据生命周期保留（进 cleaner 进程）

三组清理全部挂在 scheduler（30 秒循环保留，cleaner 负责文件扫描）：

| 清理对象 | 默认保留期 | 行为 |
| --- | --- | --- |
| 终态 Job（含工作区 `jobs/<key>/`、OUTPUT 文件与 FileRecord） | `job_retention_days=30` | rmtree 工作区 → 删 Job 行（级联 job_files/job_callbacks）→ 删 OUTPUT FileRecord 与磁盘负载 → 审计 `job.retention_delete` |
| 过期 sessions | 实时（`expires_at < now` 即清） | 批量删除 + 汇总审计 `session.sweep` |
| 过期 audit_logs | `audit_retention_days=180` | 批量删除 + 汇总审计 `audit.sweep` |

- 全部沿用既有分批模式（≤500/轮、有删除才 commit）；
- hub.yaml `retention` 节新增 `job_retention_days` 与 `audit_retention_days`；
- INPUT 快照文件仍由既有 INPUT TTL sweeper 收尾（两套清理互补不冲突）。

### 2.2 僵尸 Job reaper（进 scheduler 进程）

- `reap_stale_jobs`：`status IN (PREPARING, RUNNING) AND updated_at < now -
  (timeout_seconds + 600s 宽限)` → 置 TIMED_OUT + error_summary"Runner 失联…" +
  写 `finished_at` + 审计 `job.reap`；
- 活 runner 会持续刷新 `updated_at`（claim/transition 均触碰），因此不会误杀；
- 关联 PipelineRun 由既有 `advance_runs` 下轮自动终结为 FAILED。

### 2.3 正确性修复

- **API Key 角色钳制**：创建时请求角色层级不得超过创建者自身角色
  （`ROLE_ORDER` 比对，api_key actor 上限为其自身角色），越权 → 403 `FORBIDDEN`。
  堵住 operator 自造 admin Key 的提权口子；
- **latest_version 排序**：`_version_sort_key` 按点分整数元组排序（非数字段回退 0），
  修复 "9.0" > "10.0" 的字符串比较错误。

### 2.4 SSE 增量读

`logs_stream` 生成器改用持久文件句柄 + 字节偏移增量读（无缓冲 FileIO，offset 只
推进到完整行末尾，残行跨轮保留；终态冲刷残行）。消除"每 viewer 每秒全量重读
events.jsonl"的 IO/CPU 随任务时长线性放大问题。终态语义、300s 上限、断开回收、
Job 删除优雅收尾全部保留。

### 2.5 快修批

- metrics 渲染结果 30s 进程内缓存（`_clear_metrics_cache` 测试钩子）；
- compose.yaml 双服务加 json-file 日志轮转（后端 50m×5、Web 20m×3）。
