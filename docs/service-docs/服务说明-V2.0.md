# 服务说明 · Python Service Hub V2.0

> 本文档描述 V2.0 版本交付时系统的整体状态：功能、架构、接口、安全模型与运维方式。
> 后续版本（V2.1 起）完成时会输出对应版本的服务说明，旧版说明保留为历史档案。

## 1. 版本定位

Python Service Hub 是离线、单机的 Python 插件调度服务：业务脚本以插件形式注册，
发布者提前在目标平台构建依赖（conda-pack 或 Docker 镜像），Hub 负责插件版本管理、
文件、一次性 Job 的调度、日志与输出保存。

V2.0 在单容器双运行时与 Web 管理台（V1.x）的基础上，新增**应用层认证、四角色
RBAC、API Key 机器账号与全量写操作审计**，解决了"能访问 8080 即可操作一切"的
信任模型缺口。协议（plugin.yaml / Job Runtime / Runner Event）与既有 API 字段
完全向后兼容。

## 2. 部署形态与架构

~~~text
业务系统 / 浏览器 / hubctl
        │  HTTPS (Nginx TLS、来源限制)
        ▼
127.0.0.1:8080  ── service-hub-web（React SPA + Nginx）
                    ├── 静态页面（SPA fallback）
                    ├── 代理 /api/v1 → 127.0.0.1:8000
                    └── 拒绝 /internal/v1（404）
127.0.0.1:8000  ── service-hub（单容器）
                    ├─ hub-api        FastAPI + SQLite（无 Docker Socket）
                    ├─ conda-runner   一次性 conda-pack Job（无 Docker Socket）
                    └─ docker-runner  一次性 Docker Job（唯一 Socket 访问）
宿主机 HUB_HOST_DATA_DIR（默认 /srv/service-hub-data）= 唯一持久化点，容器内 /data
~~~

Compose 恰好两个长期服务：`service-hub`、`service-hub-web`。运行镜像：
`python-service-hub:1.0.0-linux-amd64`、`python-service-hub-web:1.0.0-linux-amd64`。

## 3. 功能模块

| 模块 | 说明 |
| --- | --- |
| 插件管理 | `.pypkg` 上传安装（conda-pack / docker 双运行时）、版本与 Build 管理、READY/ENABLED 状态与启用停用 |
| 文件管理 | 上传、按 ID 查找、复制 ID、安全命名下载；管理台保留最近 50 条本地记录 |
| 任务（Job） | Manifest 驱动创建、状态机（PENDING→…→SUCCESS/FAILED/CANCELLED/TIMED_OUT）、日志游标拉取、取消、输出下载 |
| 认证与会话 | 用户名口令登录、HttpOnly Cookie + Bearer 双通道、24h 可撤销会话、`HUB_AUTH_MODE=off` 过渡开关 |
| 角色权限（RBAC） | viewer / operator / publisher / admin 四级角色逐端点强制；API Key 机器账号同表同权限模型 |
| 审计 | 登录成功/失败、改密、上传/下载、安装、启停 Build、建/取消 Job、用户与 Key 管理——全部落库可查 |
| 用户与 Key 管理 | 管理员创建/停用用户、一次性重置口令；API Key 签发（明文仅显示一次）与吊销 |
| Web 管理台 | 中文界面：概览/插件/文件/新建任务/任务中心/任务详情/系统/用户/API Key/审计 |
| hubctl | 标准库命令行客户端：health、plugin、file、job、login/logout/whoami |

## 4. 公共 API 概览（/api/v1，除标注外需认证）

| 端点组 | 最低角色 | 说明 |
| --- | --- | --- |
| `GET /system/health` | 免认证 | 存活探测，无敏感信息 |
| `GET /system/info` | viewer | 版本/架构/Python/部署模式 |
| `GET /files`、`GET /files/{id}` | viewer | 文件列表与元数据 |
| `POST /files`、`GET /files/{id}/download` | operator | 上传与下载 |
| `GET /plugins*`、`GET /plugin-builds*` | viewer | 插件与 Build 查询 |
| `POST /plugins/install`、`POST /plugin-builds/{id}/enable\|disable` | publisher | 插件发布管理 |
| `GET /jobs*`（列表/详情/日志/输出） | viewer | 任务查询与日志 |
| `POST /jobs`、`POST /jobs/{id}/cancel` | operator | 创建与取消任务 |
| `/auth/login|logout|me|change-password` | 登录用户 | 会话管理 |
| `/users*`、`/api-keys*`、`GET /audit-logs` | admin | 治理功能 |

错误统一信封 `{success:false,error:{code,message,details}}`；认证相关错误码：
`AUTH_REQUIRED`(401)、`FORBIDDEN`(403)、`INVALID_CREDENTIALS`(401)。

## 5. 认证与安全模型

- 凭证：口令 argon2id 哈希存储；会话 token 与 API Key（`hub_` 前缀）均为 256 位随机值，
  库中只存 SHA256；API Key 明文仅在创建响应出现一次；
- 通道：浏览器走 `hub_session` Cookie（HttpOnly、SameSite=Lax、Secure 跟随转发协议）；
  hubctl 与业务系统走 `Authorization: Bearer`（显式头优先于 Cookie）；
- 引导：首次启动（required 模式）生成初始 admin，一次性口令写入数据目录
  `bootstrap-admin.json`（0600），首登提示改密；
- 吊销即时生效：登出、停用用户、吊销 Key 后对应凭证立即 401；
- 边界不变：`/internal/v1` 仍由 `HUB_RUNNER_TOKEN` 保护；`/internal/v1` 对浏览器不可达
  （Web Nginx 404）；只有 docker-runner 进程可访问 Docker Socket；
- 配置：hub.yaml `auth:{mode: required|off, session_ttl_hours: 24}`，环境变量
  `HUB_AUTH_MODE` 覆盖；YAML 裸 `off` 布尔值已兼容。

## 6. 数据持久化

`HUB_HOST_DATA_DIR` 内全部状态，备份/迁移即备份该目录：

~~~text
data/
├── db/hub.db            SQLite（插件/文件/Job/用户/Key/会话/审计）
├── files/               上传与 Job 产出文件
├── plugins/             已安装 Build 解包内容
├── jobs/                Job 工作区（job.json/result.json/logs）
├── environments/        conda-pack 解压环境
├── logs/                容器聚合日志
└── bootstrap-admin.json 初始管理员凭据（0600，改密后仍建议删除）
~~~

## 7. 部署与运维

- 全新部署：构建双镜像 → `HUB_HOST_DATA_DIR=<绝对路径> docker compose up -d` →
  浏览器 8080 登录（凭据取自数据目录 bootstrap 文件）；
- 存量升级：先以 `HUB_AUTH_MODE=off` 升级（行为等同 V1.x）→ 登录引导 admin →
  建业务账号与 API Key → 切回 required 重启；
- hubctl：`login` / `logout` / `whoami`；`HUB_TOKEN` 环境变量优先于
  `~/.hubctl/credentials`；
- 生命周期仅用 `stop/restart/up -d`；禁止 `docker compose down -v`；
- 离线发布包（`deploy/release/build-release.sh`）含双镜像、双服务 Compose、
  install/start/stop/status 脚本与 hubctl。
