# V3.0 部署验收清单（长期运行 Docker 服务）

> 适用范围：Python Service Hub V3.0 在 **Linux AMD64 Docker 主机**上的部署与验收。
> 本文档中的 Docker 真机项**只能在原生 Linux AMD64 上执行**；在 Windows/macOS 或其他
> 架构上这些步骤必须被显式标记为 skipped，不得伪装成通过。可离线验证的部分（单元测试、
> `docker compose config`）在任何平台都可执行。

## 1. 最终完成标准

只有下面所有项均为勾选状态，才算 V3.0 验收完成：

- [ ] `docker`、`docker compose`、`curl`、`jq` 可用，且 `docker info` 正常；
- [ ] 两个镜像构建成功：`python-service-hub:1.0.0-linux-amd64`、`python-service-hub-web:1.0.0-linux-amd64`；
- [ ] `HUB_HOST_DATA_DIR` 已设为绝对路径（至少两级），`docker compose up -d` 起两个容器；
- [ ] `curl -fsS http://127.0.0.1:8000/api/v1/system/health` 返回 `{"status":"UP"}`；
- [ ] 浏览器可打开 `http://127.0.0.1:8080` 并用管理员登录；
- [ ] 镜像内存在 `service-manager` 进程，且只有 `docker-runner` 与 `service-manager` 的
      运行身份在 Docker Socket 组内（`hub-api`、`conda-runner` 不在）；
- [ ] 容器内 `HUB_HOST_DATA_DIR` 之外没有把 `/var/run/docker.sock` 暴露给 Web 容器；
- [ ] 服务挂载白名单根无需额外配置：容器内 `HUB_DOCKER_HOST_DATA_ROOT` 由 entrypoint 从
      `HUB_HOST_DATA_DIR` 自动派生（二者同值），未配置时任何带挂载的部署都会被 422 拒绝；
- [ ] 部署服务前已 `docker load` 目标镜像（离线模型下不做隐式拉取，未知镜像返回
      `422 SERVICE_IMAGE_MISSING`）；
- [ ] 通过管理台成功部署 `nginxdemos/hello` 服务，实际状态为 `running`；
- [ ] 该服务端口只能从宿主机回环访问，且容器名为 `hub-svc-<name>`；
- [ ] 边界拒绝项均返回 422 且不创建容器：挂载 `/etc` 或 `/var/run/docker.sock`
      （`SERVICE_MOUNT_FORBIDDEN`）、host 端口 80/8000/8001/8080、用户 `0:0`；
- [ ] 「日志」弹窗能看到容器输出；
- [ ] 停止 → 启动 → 重启 → 删除全流程行为正确，期望状态随之变化；
- [ ] 非管理员看不到「删除」按钮，直接调用写接口返回 403；
- [ ] `service-manager` 不可用时，前端显示「service-manager 不可用」而非原始 502 文本；
- [ ] 实施证据（截图、命令输出、审计记录）已归档。

## 2. 部署结构（V3.0 视角）

Compose 仍然只有两个长期运行服务：

| 服务 | 端口 | 挂载 | 说明 |
|---|---|---|---|
| service-hub | `127.0.0.1:8000:8000` | `<HUB_HOST_DATA_DIR>:/data`、`/var/run/docker.sock` | API + Runner + cleaner/scheduler/service-manager |
| service-hub-web | `127.0.0.1:8080:8080` | 无 | SPA + 反向代理，**不挂载 `/data` 与 Docker Socket** |

`service-hub` 容器内由 supervisord 管理的进程：

```text
hub-api           → 0.0.0.0:8000     无 Socket
conda-runner                         无 Socket
docker-runner                        ✔ Socket（一次性 Job）
cleaner / scheduler                  无 Socket
service-manager   → 127.0.0.1:8001   ✔ Socket（V3.0 长期服务）
```

调用链：

```text
浏览器 → Web 管理台 → /api/v1/services → hub-api ──Bearer 内部令牌──► service-manager
                                            │                              │
                                            └── SQLite service_defs ───────┴──► hub-svc-<name>
```

## 3. 端到端验收步骤

### 3.1 启动与登录

```bash
cd /srv/python-service-hub
sudo install -d -m 0750 /srv/service-hub-data
sudo docker build -t python-service-hub:1.0.0-linux-amd64 .
sudo docker build -t python-service-hub-web:1.0.0-linux-amd64 web
sudo HUB_HOST_DATA_DIR=/srv/service-hub-data docker compose up -d
curl -fsS http://127.0.0.1:8000/api/v1/system/health       # {"status":"UP"}
```

首次启动的管理员凭据在数据目录 `bootstrap-admin.json`（默认需改密）：

```bash
sudo jq . /srv/service-hub-data/bootstrap-admin.json
```

用该账号登录 `http://127.0.0.1:8080`，完成后先按提示修改密码。

### 3.2 确认 Socket 边界

```bash
# 两个镜像内都应存在 service-manager 程序
docker exec <hub-container> supervisorctl -c /etc/service-hub/supervisord.conf status

# 运行身份与组归属：hub-api / conda-runner 必须不在 Socket 组内
docker exec <hub-container> id hub-api
docker exec <hub-container> id conda-runner
docker exec <hub-container> id docker-runner
docker exec <hub-container> id service-mgr
```

预期：`docker-runner` 与 `service-mgr` 的 groups 中含 Socket 所属组，`hub-api`、
`conda-runner` 不含。Web 容器不应出现 `/data` 或 `docker.sock` 挂载：

```bash
docker inspect --format '{{json .Mounts}}' <web-container>
```

### 3.3 部署示例服务

在管理台进入「服务」→「部署服务」：

| 字段 | 取值 |
|---|---|
| 名称 | `hello` |
| 镜像 | `nginxdemos/hello` |
| 端口映射 | 宿主 `18080` → 容器 `80` |
| 环境变量 | 留空，或 `TZ=Asia/Shanghai` |
| 挂载 | 留空 |
| 启动命令 | 留空 |

提交后列表出现 `hello`，期望状态 `RUNNING`，实际状态应在几秒内变为 `running`。

也可以用 API 直接验证（若启用了认证，先取 Token 并带 `Authorization` 头）：

```bash
curl -fsS -X POST http://127.0.0.1:8000/api/v1/services \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer <token>" \
  -d '{"name":"hello","image":"nginxdemos/hello","ports":[{"host":18080,"container":80}],"env":{},"mounts":[]}'
```

### 3.4 回环端口访问

```bash
docker ps --filter name=hub-svc-hello --format '{{.Names}}\t{{.Ports}}'   # 应为 127.0.0.1:18080->80/tcp
curl -fsS http://127.0.0.1:18080/ | head -n 5
```

**边界检查**：从另一台机器访问 `http://<server-ip>:18080/` 应当**失败**，因为端口只绑定
回环地址。若需要对外提供，必须由宿主机 Nginx 等受控代理显式转发。

### 3.5 查看日志

管理台点「日志」，弹窗显示 `nginxdemos/hello` 的访问日志；调整「尾部行数」并「刷新」，
内容应随之变化。也可以：

```bash
curl -fsS -H "Authorization: Bearer <token>" \
  'http://127.0.0.1:8000/api/v1/services/hello/logs?tail=50'
```

### 3.6 停止 / 启动 / 重启 / 删除

1. 「停止」→ 期望状态变 `STOPPED`，实际状态变 `exited`，`curl http://127.0.0.1:18080/` 失败；
2. 「启动」→ 实际状态回到 `running`，端口恢复可访问；
3. 「重启」→ 容器重启，访问恢复正常；
4. 「删除」（需确认）→ 容器被移除，列表不再出现该服务。

```bash
docker ps -a --filter name=hub-svc-hello        # 删除后应无输出
```

### 3.7 权限边界

- 用 operator/viewer 账号登录：列表可见，但**看不到「删除」按钮**，启动/停止/重启也
  不会出现；直接调用写接口应返回 403：

```bash
curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  -H "Authorization: Bearer <non-admin-token>" \
  -H 'Content-Type: application/json' \
  -d '{"name":"x","image":"nginxdemos/hello","ports":[],"env":{},"mounts":[]}' \
  http://127.0.0.1:8000/api/v1/services        # 403
```

### 3.8 失败降级

在容器内临时停掉 service-manager，管理台刷新「服务」页或打开日志，应显示
**「service-manager 不可用」**，而不是原始网关 502 文本：

```bash
docker exec <hub-container> supervisorctl -c /etc/service-hub/supervisord.conf stop service-manager
# 页面应显示 service-manager 不可用
docker exec <hub-container> supervisorctl -c /etc/service-hub/supervisord.conf start service-manager
```

## 4. 失败排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `GET /api/v1/services` 返回 502 | service-manager 未启动 / 令牌不一致 | `supervisorctl status`；确认 `HUB_RUNNER_TOKEN` 已注入两个进程 |
| 部署返回 502 且定义变 `STOPPED` | Docker Socket 权限不足 | 检查 `service-mgr` 是否在 Socket 组内（见 3.2） |
| 部署返回 502 且报镜像拉取失败 | 目标机离线或无镜像 | 预先 `docker pull`/`docker load` 目标镜像 |
| 端口探测能通但外部访问不了 | 端口只绑 `127.0.0.1` | 属预期行为；需对外时配置宿主机反向代理 |
| 日志弹窗空白 | 容器已退出或尚无输出 | 确认实际状态为 `running`；调大 tail 后刷新 |
| 创建报 `SERVICE_NAME_TAKEN` | 同名定义已存在 | 换名，或先删除已有服务 |
| 更新报 `SERVICE_NAME_IMMUTABLE` | `PUT` 请求体里的 `name` 与路径不一致 | 保持两者一致；改名需先删后建 |
| 删除后容器仍在 | 容器非由 Hub 管理（名字不符 `hub-svc-<name>`） | 只应通过 Hub API 管理受控容器 |
| 非管理员能看到删除按钮 | 前端角色判定异常 | 确认 `GET /api/v1/auth/me` 返回的 `role` 正确 |

## 5. 门禁命令

任何平台（含 Windows 开发机）可执行：

```bash
python -m pytest -m "not integration"
python -m ruff check .
python -m mypy packages
HUB_HOST_DATA_DIR=/srv/service-hub-data docker compose config --quiet
cd web && npm run test:run && npm run typecheck && npm run lint && npm run build
```

仅原生 Linux AMD64 Docker 主机可执行（其余平台会 skip）：

```bash
python -m pytest -m integration tests/integration/test_web_console_lifecycle.py -v
python -m pytest -m integration tests/server/test_container_smoke.py -v
```

> `tests/integration/test_web_console_lifecycle.py` 与 `test_container_smoke.py` 中的
> Docker 真机用例通过 `sys.platform != "linux"` 或非 x86_64/amd64 时 `pytest.skip`
> 主动跳过，保证这些用例在开发机上**不会被记为通过**。
