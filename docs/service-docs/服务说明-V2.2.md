# 服务说明 · Python Service Hub V2.2

> 本文档描述 V2.2 交付时系统的整体状态。基础说明见
> [服务说明-V2.0](服务说明-V2.0.md) 与增量 [服务说明-V2.1](服务说明-V2.1.md)；
> 本文仅详述 V2.2 的增量与最终形态。

## 1. 版本定位

V2.2 在认证（V2.0）与资源治理（V2.1）之上交付**自动化闭环**，把"人守着页面点"
升级为"链路自动跑"：Job 终态自动回调业务系统、按周期自动创建 Job、多步任务
自动步进。协议与既有 API 字段仍完全向后兼容（`POST /jobs` 仅新增可选 `callback`
字段）。

## 2. V2.2 新增能力

### 2.1 Webhook 回调

- `POST /jobs` 请求体新增可选 `"callback": {"url", "secret"}`；
- Job 到达终态（SUCCESS/FAILED/CANCELLED/TIMED_OUT）后，scheduler 进程 POST：
  body `{"job_id","status","error_summary"}`；有 secret 时带头
  `X-Hub-Signature: sha256=<HMAC-SHA256(body, secret)>`；
- 重试：最多 3 次，退避 60s×attempts；状态机 PENDING→(SUCCEEDED|FAILED→EXHAUSTED)；
- 查询：`GET /api/v1/jobs/{job_key}/callbacks`（viewer，不回传 secret）；
  管理台任务详情页"Webhook 回调"卡可视化；每次投递写审计。

### 2.2 定时任务

- `POST /api/v1/schedules`（operator+）：name/plugin/version/runtime/inputs/params/
  interval_minutes；`GET` 列表；`enable|disable`（operator+）；`DELETE`（admin）；
- scheduler 每 30s 扫描到期规则自动创建 Job（`next_run_at` 推进一个间隔）；
  Build 缺失等失败审计 denied 且不推进，不阻塞后续周期；
- 管理台"定时任务"页：列表/新建/启停/删除（403 场景有明确提示）。

### 2.3 线性管道

- `POST /api/v1/pipelines`（operator+）：定义步骤链，下一步输入用
  `"$prev.<上一步输出 logical_name>"` 引用上一步产物（首步禁用 `$prev`，422）；
- `POST /pipelines/{id}/execute`：创建 run（RUNNING）与第一步 Job；
- scheduler 自动步进：SUCCESS → 收集 OUTPUT 文件（logical_name→file_key）替换下一
  步 `$prev` 引用并创建下一步 Job；任一步失败（或 `$prev` 引用不存在）→ run=FAILED
  不再步进；无下一步 → run=SUCCEEDED；
- `GET /pipeline-runs?pipeline_id=`（viewer）查看进度；管理台"管道"页可执行、
  展开行显示运行列表与状态 Tag。

## 3. 进程与数据模型增量

- supervisord 第五受管进程 `[program:scheduler]`（hub-api 用户），注册三个 sweep：
  `deliver_due`（回调）/ `trigger_due`（定时）/ `advance_runs`（管道步进）；
  崩溃自动重启；healthcheck 必需清单扩为五进程；
- 迁移 0005 新表：`job_callbacks`、`schedules`、`pipelines`、`pipeline_runs`；
  `jobs` 增 `pipeline_run_id`（SET NULL）；
- 全部触发/投递/步进状态落库，scheduler 崩溃重启后可续。

## 4. 质量与验收状态

- 开发机门禁（V2.2 完成时）：python 非集成 **256+ passed**（含回调投递 13、定时
  19、管道 19 等新增用例）、ruff/mypy strict 通过、web **153 passed** +
  typecheck/lint/build 通过、`docker compose config` 通过；
- Linux AMD64 验收：`tests/integration/test_automation_lifecycle.py`（本地 HTTP stub
  校验回调 HMAC 签名、scheduler 触发、管道步进）清单见验收报告第 10 节。

## 5. 已知限制与后续路线

- 回调/调度间隔为分钟级固定间隔（非 cron 表达式）；管道仅线性、无分支汇聚；
- 回调失败重试 3 次后 EXHAUSTED，暂无人工重放端点；
- 后续路线：V2.3 插件仓库（Hub-to-Hub 同步）、分片/秒传上传、SSE 实时日志；
  V3.0 长期运行 Docker 服务。
