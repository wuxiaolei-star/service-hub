# 服务说明 · Python Service Hub V4.0-alpha

> 本文档描述 V4.0-alpha（Phase 1）交付时系统的整体状态。
> 基础与历史增量见 [服务说明-V2.0](服务说明-V2.0.md) → [服务说明-V3.3](服务说明-V3.3.md)。

## 1. 版本定位

V4.0-alpha 是从"单体重构为插件化架构"的第一个里程碑。后端从单体 FastAPI app
演进为**最小内核 + FeaturePlugin 体系**：内核只做 HTTP/DB/调度/事件四件事，
所有功能域通过 FeaturePlugin 协议自注册。本阶段完成了内核基础设施和首批两个
插件拆分（schedules + webhooks），验证了插件机制的四个接触面。

**零 API 破坏、零迁移新增、零业务逻辑改动。**

## 2. 新增架构组件

### 2.1 FeaturePlugin 协议（`kernel/protocol.py`）

每个功能插件声明：name、depends_on（硬依赖）、soft_depends_on（软依赖）、
models（自有 ORM 模型）、routers、scheduler_tasks、event_handlers。
内核按 `depends_on` 拓扑排序加载，硬依赖缺失拒绝启动。

### 2.2 Plugin Registry（`kernel/registry.py`）

`resolve_plugins(catalog, enabled)`：严格校验（不做静默补齐）+ Kahn 拓扑排序 +
环检测。`enabled=None` 取 `default_enabled=True` 的全部插件。

### 2.3 Event Bus（`kernel/events.py`）

进程内同步分发 + SQLite outbox 跨进程投递（at-least-once，≤30s）。
`emit` 不阻塞业务事务；handler 异常记日志不中断。

### 2.4 插件包结构

```text
hub_server/plugins/
├── __init__.py
├── schedules_plugin.py   SchedulesPlugin(BaseFeaturePlugin)
└── webhooks_plugin.py    WebhooksPlugin(BaseFeaturePlugin)
```

### 2.5 前置迁移

- `0010_kernel_event_log`：`hub_events` outbox 表（跨进程事件投递）
- 解除 `jobs.pipeline_run_id → pipeline_runs.id` 反向 FK（改为逻辑引用）
- 解除 `routers/jobs.py → routers/files.py` 的 `_file_response` 耦合
