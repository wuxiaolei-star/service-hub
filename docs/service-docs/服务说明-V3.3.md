## 1. 版本定位

文件删除自助 + 引用保护、审计/任务 CSV 导出、服务 reconcile 自愈。
迁移 0009 新表 `webhook_deliveries`。

## 2. V3.3 新增能力

### 2.1 备份空间预检

`POST /system/backup` 在写 tar.gz 前校验磁盘剩余空间 ≥ 预估数据目录大小 × 1.3
（排除 backups/environments/logs），不足 → 409 `DISK_SPACE_INSUFFICIENT`
（details 含 free/needed）。防止备份本身打满 40G 盘。

### 2.2 Webhook 投递明细

- 新表 `webhook_deliveries`（callback_id FK CASCADE, attempted_at, status_code,
  ok, error），每次投递（成功/失败/传输异常）写一行；
- `GET /jobs/{key}/callbacks/{callback_id}/deliveries`（viewer）按时间倒序返回
  逐次投递历史（限 100 条），解决"EXHAUSTED 后只有最后一次结果可看"的排查盲区。

### 2.3 文件删除自助

- `DELETE /api/v1/files/{file_key}`（operator+）：
  被 Job 引用 → 409 `FILE_IN_USE`；正常 → unlink 磁盘负载 + 删 FileRecord +
  审计 `file.delete` → 204；
- 与 V3.1 INPUT TTL 清理互补：用户可即时删除确定不再需要的文件，不必等 TTL。

### 2.4 CSV 导出

- `GET /api/v1/audit-logs/export`（admin，text/csv 流式）：全部审计按时间升序，
  8 列含 CSV 注入防护（`=`/`+`/`-`/`@` 前置 `'`）；
- `GET /api/v1/jobs/export`（operator+，text/csv 流式）：最近 10000 条 Job
  （joinedload 避免 N+1），9 列含同样防护。

### 2.5 服务 reconcile

- scheduler 注册 `reconcile_service_containers` 任务：遍历 desired_state=RUNNING
  的 ServiceDef → 调 service-manager status → 容器非 running → client.start +
  审计 `service.reconcile`；status 不可达 → 汇总一条 denied 不崩。
