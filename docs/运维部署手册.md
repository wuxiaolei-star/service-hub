# Service Hub 运维部署手册

> 本手册面向**负责部署和日常运维**的工程师，假设你从未接触过本项目。
> 目标：30 分钟内完成部署，10 分钟内完成日常巡检。

---

## 一、前置条件

| 项 | 要求 | 检查命令 |
|---|---|---|
| 操作系统 | Linux AMD64（Ubuntu 22.04+ / RHEL 9+） | `uname -m` → x86_64 |
| Docker Engine | 24.0+ | `docker version` |
| Docker Compose | v2.20+ | `docker compose version` |
| 磁盘 | ≥20GB 可用（数据 + 镜像 + 日志） | `df -h /` |
| 内存 | ≥4GB | `free -h` |
| 网络 | 能访问 Docker Hub 或离线导入镜像 | — |

---

## 二、部署方式选择

| 方式 | 适用场景 | 耗时 |
|---|---|---|
| **A：离线发布包** | 服务器无外网或有安全管控 | ~15 分钟 |
| **B：源码构建** | 服务器可访问 PyPI / Docker Hub | ~20 分钟 |

---

## 方式 A：离线发布包部署

### A-1 在有外网的机器上制作发布包

```bash
cd /path/to/service-hub
bash deploy/release/build-release.sh
# 产出：dist/service-hub-1.0.0-linux-amd64.tar.gz
```

### A-2 传输到目标服务器

```bash
scp dist/service-hub-1.0.0-linux-amd64.tar.gz user@server:/opt/service-hub/
```

### A-3 在服务器上安装

```bash
cd /opt/service-hub
tar -xzf service-hub-1.0.0-linux-amd64.tar.gz
cd service-hub-linux-amd64

# 设置数据目录（唯一必填变量）
export HUB_HOST_DATA_DIR=/srv/service-hub-data

# 安装（校验 SHA256 → 加载双镜像 → 创建数据目录 → 写 .env）
sudo ./install.sh

# 启动
sudo ./start.sh

# 验证
sudo ./status.sh
```

## 方式 B：源码构建部署

```bash
# 1. 克隆仓库
git clone <repo-url> /opt/service-hub/src
cd /opt/service-hub/src

# 2. 创建数据目录
sudo mkdir -p /srv/service-hub-data

# 3. 构建双镜像
docker build -t python-service-hub:1.0.0-linux-amd64 .
docker build -t python-service-hub-web:1.0.0-linux-amd64 web

# 4. 启动（唯一必填变量）
sudo HUB_HOST_DATA_DIR=/srv/service-hub-data docker compose up -d

# 5. 验证
curl http://127.0.0.1:8000/api/v1/system/health   # {"status":"UP"}
curl -I http://127.0.0.1:8080/                     # 200
```

## 三、首次配置

### 3.1 获取初始管理员凭据

首次启动时系统自动生成管理员账号，凭据写入数据目录：

```bash
cat /srv/service-hub-data/bootstrap-admin.json
# {"username": "admin", "password": "<一次性随机口令>"}
```

### 3.2 登录并修改口令

1. 浏览器打开 `http://<服务器IP>:8080`（或经 Nginx TLS 的 8443）
2. 使用 bootstrap-admin.json 中的用户名/口令登录
3. 系统会提示修改口令 → 设置新口令
4. **删除 bootstrap-admin.json**

### 3.3 创建业务账号和 API Key

1. 管理台 → 用户管理 → 新建用户（选择角色）
2. 管理台 → API Key → 新建 Key（选择角色）→ **Key 只显示一次，立即保存**
3. 业务系统使用 API Key 调用 API（`Authorization: Bearer hub_...`）

### 3.4 角色说明

| 角色 | 上传文件 | 建/取消 Job | 安装/启停插件 | 用户管理 | 审计查询 |
|---|---|---|---|---|---|
| viewer | ❌ | ❌ | ❌ | ❌ | ❌ |
| operator | ✅ | ✅ | ❌ | ❌ | ❌ |
| publisher | ✅ | ✅ | ✅ | ❌ | ❌ |
| admin | ✅ | ✅ | ✅ | ✅ | ✅ |

## 四、日常运维

### 4.1 服务管理

```bash
cd /opt/service-hub/src   # 或发布包目录

# 查看状态
docker compose ps
curl http://127.0.0.1:8000/api/v1/system/health

# 重启（数据不受影响）
docker compose restart

# 停止
docker compose stop

# 启动
docker compose up -d
```

> ⚠️ 禁止 `docker compose down -v`（会删卷导致数据丢失）。

### 4.2 查看日志

```bash
docker compose logs -f service-hub        # 后端 6 进程聚合日志
docker compose logs -f service-hub-web    # Nginx 访问日志
```

### 4.3 数据备份

```bash
# 方式 1：hubctl（推荐）
python tools/hubctl backup create --output /backup/

# 方式 2：手动 tar
docker compose stop
tar -czf /backup/service-hub-$(date +%F).tar.gz -C /srv service-hub-data
docker compose up -d
```

### 4.4 版本升级

```bash
# 1. 备份
tar -czf /backup/pre-upgrade-$(date +%F).tar.gz -C /srv service-hub-data

# 2. 导入新镜像
docker load -i service-hub-image.tar

# 3. 重启
docker compose up -d

# 4. 验证
curl http://127.0.0.1:8000/api/v1/system/health
```

## 五、使用插件

### 5.1 安装计算插件

```bash
# 方式 1：管理台（插件页 → 上传 .pypkg）
# 方式 2：hubctl
python tools/hubctl plugin install path/to/nc_to_shp-1.0.0-linux-amd64-docker.pypkg
```

安装后 Build 状态从 INSTALLING → READY，需手动启用（ENABLED）才能创建 Job。

### 5.2 创建 Job

```bash
# 上传输入文件
python tools/hubctl file upload sample.nc
# 返回 file_id

# 创建 Job
python tools/hubctl job run nc_to_shp \
    --version 1.0.0 --runtime docker \
    --input source_nc=<file_id> \
    --params params.json
```

### 5.3 查看/下载结果

```bash
python tools/hubctl job status <job_id>
python tools/hubctl job download <job_id> --output ./results/
```

## 六、常见故障排查

| 故障 | 排查步骤 |
|---|---|
| 后端 unhealthy | `docker compose logs service-hub` → 看 6 进程哪个异常 |
| Web 502 | 后端未 healthy，`docker compose ps` 确认 |
| 登录返回 401 | 凭据错误或会话过期；检查 bootstrap-admin.json 是否已删除 |
| 上传返回 409 | 配额已满或文件名冲突；检查 `quotas` 配置 |
| Job 卡在 PENDING | 无 ENABLED Build 或 Runner 异常；检查 plugin-builds 状态 |
| 插件安装返回 4xx | 包格式/SHA256 校验失败；核对发布者提供的 SHA256 |
| 磁盘不足 | `df -h` → 清理 backups/ 或旧 Job 输出 |

## 七、安全基线

- Hub 仅监听 `127.0.0.1`（8000/8080），对外暴露必须经 TLS 反向代理
- 生产环境必须修改初始管理员口令
- 禁用插件：hub.yaml `auth.mode: off` 仅限过渡期
- `/internal/v1` 端点仅供 Runner 使用，Nginx 层已拒绝外部访问
- Docker Socket 仅 docker-runner 和 service-manager 进程可访问
- 所有写操作（含登录失败）落审计日志
